# Changelog

Releases before 0.14.1 are described in the README sections (each names the version that brought it) and in the git history.

## 0.14.2 (2026-10-17)

A patch to the generated CSS: **an element with the `hidden` attribute is hidden whatever `display` its class gives it.**

- **`[hidden]` wins over the author's `display`.** The browser's own `[hidden] { display: none }` loses to any `display` a Style gives the element (`Flow` writes `display: flex` or `grid`), so an element a page or an escape marked `hidden` stayed on screen. The generated CSS now carries `[hidden]:not([hidden=until-found i]) { display: none !important; }`, once outside a layer and once inside `@layer yumemi-hidden` (as the closed `<dialog>` rule of 0.12.1 does; a `!important` inside a layer beats one outside it). It applies to every face, with or without `Live`, in `style.css` and in the page's `<style>`.
- **`hidden="until-found"` is left alone.** The browser hides that value with `content-visibility: hidden`, not `display: none`, so that find-in-page and URL fragments can open it; forcing `display: none` would stop that.
- **`el.fresh`'s own rule is folded in.** The `[data-yumemi-fresh][hidden] { display: none !important; }` line of `Live` faces is gone; the new rule covers the same element, so it stays hidden exactly as before.
- **What can change on screen.** An element that carries `hidden` and was shown anyway by its class's `display` (or by an inline `display`) is now hidden; remove the attribute to show it, as the `Live` refresh and the escapes already do. Regenerating a face rewrites `style.css`, the page's CSS in `src/gen/shell.mjs` and nothing else.

## 0.14.1 (2026-10-17)

Adds to 0.14.0 and narrows one thing it did: **reads that are not a `Live` Block's read no longer carry a token.** The token's form, the socket, the signal and `YumemiLive` are as they were.

- **Tokens only for `Live` Blocks' reads (changed from 0.14.0).** In 0.14.0 every read Service with a root Entity answered with an `x-yumemi-live` token. A public read (an `Anyone` clause in its `allow`) thereby handed a token to anyone, signed in or not, and that token heard every write under the same root as it committed, including writes the public may not see (one word, no body, but at any time). Now the `live` table in the api's `src/gen/registry.mjs` lists, besides every write with a root Entity, only the read Services of Blocks that some face's Page places as `Live`; the generator knows them because it writes the api and the faces in one run. Any other read answers without the header (not an empty one). A page holding a 0.14.0 token gets the new rule's token, or none, when it next reads. The socket checks the token, not the table, so a 0.14.0 token (one taken from a public read, say) still opens a socket and hears until it expires, at most one hour after the upgrade; changing `YUMEMI_LIVE_KEY` without `YUMEMI_LIVE_KEY_PREVIOUS` when upgrading refuses those tokens (`signature`) and the `Live` pages read again for new ones, while sockets already open end at their token's expiry at the latest. Apps whose reads were never `Live` see the read rows leave `registry.mjs` and nothing else.
- **`Live` on a public read stops the generator (exit 4).** A `Live` Block whose read Service has an `Anyone` clause is a contradiction (`… の allow に Anyone がある …`): its token would let anyone hear the root's writes. So does a `Party` × `NoOwner` clause, in any `at` (`… の allow の句 Party(owner: NoOwner)は session があれば誰でも root のどの行も通す …`): anyone with a session passes on any row of the root, so a signed-in third party, which in an app where anyone may sign up is anyone, could hear the root's writes. A clause the generator cannot read (a constant, a spread, an `allow` that is not a List literal) stops it too (`… の allow の句が読めない: …`), since it cannot tell. An Entity subject × `NoOwner` (`Staff`, `AsFan`, `allow.staff`) is named in a warning (exit 0). Make the Block's read one only the root's parties pass: every clause's `owner` `Self` or `Via<Entity>Party` (a chat read allowed as `AsMember` × `ViaMemberParty` and `AsGuest` × `ViaGuestParty` passes). This narrows who holds a token, not what it hears: a party of the root still hears the time of writes under that root it may not read itself, which is ★'s call.

- **The fragment answer serves `Fixed` Blocks too.** A GET of a page URL with `x-yumemi-block: <name>` answers for every `Fixed` Block of the Page's `sp` placements, on every face, not only for `Live` Blocks. Gate, Vars, session and reads are the same as for the page (the Block's read Service and the Page's and Layout's reads that are not `optional`); a Block that reads no Service is drawn from the Vars. The answer is `<style>` and `<yumemi-block name>` (`display: contents`, no token). Layout Blocks, `Widget` Blocks and names the Page does not place stay 404, before any read.
- **`yumemi.block` on every face with escapes.** `mount(element, yumemi)` gets `yumemi.block(name, { href })` whether or not the face has `Live`. For a `Fixed` Block it returns a detached `<yumemi-block href>` with its style rules added; calling it again with the same URL reads the placed element again and applies it in place (the morph of `Live`). It returns `null` when no fragment comes, and never reloads the page for a `<yumemi-block>`.
- **The client runtime is split.** `yumemi/front/block.mjs` holds the fragment fetch, the style rules and the morph; `yumemi/front/live_block.mjs` (tokens, socket, scroll, `el.fresh`) builds on it. A face without `Live` bundles `block.mjs` only, and only when it has escapes.
- **Generated output.** Faces whose Pages place `Fixed` Blocks get `block_<name>` functions in `src/gen/load/**`, a `blocks` table and the fragment answer in `src/gen/shell.mjs`, and the header check in `src/gen/gate.mjs`. The page HTML is unchanged.
