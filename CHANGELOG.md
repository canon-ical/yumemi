# Changelog

Releases before 0.14.1 are described in the README sections (each names the version that brought it) and in the git history.

## 0.14.7 (2026-10-18)

Fixes the client navigation sending a GET twice when the link's target answers with a redirect.

- **A redirect is followed once.** The navigation fetch used `redirect: "manual"`, so a 302 became an opaque response and the page was then loaded again from the *same* URL, which ran a side-effecting GET twice. The fetch is now `redirect: "follow"` with `mode: "same-origin"`; a redirected response is not swapped in but its final URL is opened as a page load (`location.replace`), so the URL and the CSP header are the final page's. The original `#` is kept; `fetch` does not see a `#` in `Location`, so a redirect whose `Location` has one lands without it.
- **The final page is requested twice instead.** On a same-origin redirect the server now sees the original URL and each URL on the way once, and the final URL twice: by the fetch (with `x-yumemi-navigate: 1`) and by the page load. In 0.14.6 the original URL was requested twice and the final URL once.
- **Other origins.** `mode: "same-origin"` makes the fetch fail before a request leaves for another origin; the failure falls back to loading the original URL, as before.
- Responses that do not redirect (200, failure pages, a CSP that differs, not HTML) and network failures or aborts behave as in 0.14.6.

## 0.14.6 (2026-10-17)

Adds a `server.Storage` declaration, **`ReadFrom`**: an Entity's generated reads read another relation (a view) than its table, while the verbs and the foreign keys keep the table. An app that declares no `ReadFrom` generates what 0.14.5 generated, byte for byte.

- **`ReadFrom(entity:, relation:)`.** `relation` is a name in the Entity's schema (`app`, or its `InSchema` schema). The generated reads name `<schema>.<relation>` wherever they named the table: `FROM`, `JOIN`, the relation reads (`to_<property>`), the `has` `EXISTS`, the `allow` clauses' nested `EXISTS` and the `with` children. The verbs (create, update, put, delete, `RETURNING`, the statements that lock rows) still write and lock the table.
- **With `Derived`.** On an Entity with `ReadFrom`, the read-side stops of 0.14.5 are lifted: a generated read may hand the Entity's whole rows (`t.*`, `to_jsonb`, a `with` child, a relation read) and name a `Derived` Property (`where`, `order`, `group`, `Pick`, keyset, the `allow` owner's `party`, a `with` child's `order`), since the relation carries those columns. The write side is unchanged: `Derived` Properties stay out of the verbs, `Draft` and `Created`. An Entity with `Derived` and no `ReadFrom` stops as in 0.14.5. `ReadFrom` without `Derived` is allowed.
- **Stops (exit 4).** A relation that is not a plain SQL identifier (`[a-z_][a-z0-9_]*`, so no schema prefix), a second `ReadFrom` for the Entity, `ReadFrom` on an `InObject` Entity, or one naming no Entity.
- **The relation is the app's DDL.** Its columns must be the table's plus the `Derived` ones, under the Properties' column names; the row decoders read them as before. `FOR UPDATE` cannot lock a view over an outer join, which is why the verbs keep the table.

## 0.14.5 (2026-10-17)

Adds two `server.Storage` declarations: **`InSchema`** puts an Entity's table in another schema than `app`, and **`Derived`** declares a Property the table has no column for. An app that declares neither generates what 0.14.4 generated, byte for byte.

- **`InSchema(entity:, schema:)`.** The generated SQL names that Entity's table `<schema>.<table>` wherever it named `app.<table>`: verbs, reads, joins, `EXISTS`, `with` children, relation reads and `allow` clauses. A schema that is not a plain SQL identifier, `framework`, a second `InSchema` for the Entity, or `InSchema` on an `InObject` Entity stops the generator (exit 4).
- **`Derived(entity:, property:)`.** The read SQL hands the value in from another table (a `JOIN`) under the Property's name; the row decoders read it as before. The generator leaves the Property out of the create and update verbs (columns, values, `RETURNING`), `Draft`, `Created` and the runtime's verb table, and writes no `update_<entity>_<property>`. A generated read that would hand the Entity's whole rows (`t.*`, `to_jsonb`, a `with` child or a relation read) or name the Property is not written and stops the generator (exit 4); write it by hand (`ManualRead`, the root statement) or pick the other columns with `q.Pick`. `Derived` on a key, `auto_key`, `upsert_key`, the `ordered_by` columns, `version`, the phase, a relation, a field of `verbs.Update` or `verbs.DeleteWhere`, an `InObject` Entity, or together with `Column`, `Text`, `Split`, `Array` or another `Derived` on the same Property stops the generator (exit 4).
- **For apps that adopt `Derived`:** `Draft` and `Created` lose the field, so code that builds the Draft with it or reads it from `Created` stops compiling; `update_<entity>_<property>` is gone from `gen/verb`.

## 0.14.4 (2026-10-17)

Adds **`PaddingLeft`**, a `SpaceProperty` that sets only the left inner padding (`padding-left`).

- Pair it with `Border(edge: LeftEdge, ..)` to open the gap between a bar and the text beside it without touching the top, bottom or right padding. `Padding` still writes all four sides, as before.

## 0.14.3 (2026-10-17)

Adds **the failure page**: a face that declares one in `src/failure.gleam` answers a failing page request (403, 404, 5xx, an exception) with that page, with the original status code (inside its Layout once the gate has let the requester through), also within client navigation. Faces that do not declare one generate what 0.14.2 generated.

- **`src/failure.gleam`** holds `pub const page: Page(..)`. A new variable source, `Failure`, gives its Block `"forbidden"` (401, 403), `"not_found"` (other 4xx) or `"unavailable"` (5xx, exceptions). Article 45 keeps the page drawable from any URL without the API: `of: None`, `Fixed` placements whose Blocks read nothing, vars `Failure` and `CurrentRoute` (`""`), and no `Fixed` read in the Layout; `Failure` elsewhere stops the generator. The Layout's Widgets are read and left out when their read fails.
- **Only page requests** (`GET` / `HEAD`, no `x-yumemi-block`, and `sec-fetch-dest: document`, `accept` with `text/html`, or `x-yumemi-navigate`) get the page. The fragment answer, assets, island and test fetches, and a `Deny`'s body for non-page requests stay plain text as before.
- **Shell and gate.** The shell's failures, the gate's 403 / 404 / 503 and `Deny`, and exceptions (now caught and logged as a 500) become the page, with `x-yumemi-failure: <status>`, `cache-control: no-store` and the route's CSP (for an unmatched path, the CSP of the `Every` declarations). **The gate's own failures have no frame:** they show only the failure page's Blocks, without the Layout and without reading its Widgets, since the gate has not let the requester in. If the page itself cannot be drawn (a missing `Origin` env var, a throwing render), the plain text goes out; the page never wraps itself.
- **Unmatched paths meet the gate** on a face with a failure page: a page request for a path no Page matches goes through the checks of the gate's `Every` rules first, so the Layout around a 404 is shown only to whom the face admits; those it stops get the frameless page or a redirect.
- **Client navigation** (`navigate.mjs`) swaps in a response marked `x-yumemi-failure` like a 200, instead of reloading the page, so the failure shows in place and back works. This is the one change faces without a failure page carry: their bundled `client.mjs` gets the new check, and they never send the header, so nothing they do changes.
- **For entries:** `src/gen/shell.mjs` exports `failure(request, env, status)` (the page for a page request, plain text otherwise).

## 0.14.2 (2026-10-17)

A patch to the generated CSS: **an element with the `hidden` attribute is hidden whatever `display` its class gives it.**

- **`[hidden]` wins over the author's `display`.** The browser's own `[hidden] { display: none }` loses to any `display` a Style gives the element (`Flow` writes `display: flex` or `grid`), so an element a page or an escape marked `hidden` stayed on screen. The generated CSS now carries `[hidden]:not([hidden=until-found i]) { display: none !important; }`, once outside a layer and once inside `@layer yumemi-hidden` (as the closed `<dialog>` rule of 0.12.1 does; a `!important` inside a layer beats one outside it). It applies to every face, with or without `Live`, in `style.css` and in the page's `<style>`.
- **`hidden="until-found"` is left alone.** The browser hides that value with `content-visibility: hidden`, not `display: none`, so that find-in-page and URL fragments can open it; forcing `display: none` would stop that.
- **`el.fresh`'s own rule is folded in.** The `[data-yumemi-fresh][hidden] { display: none !important; }` line of `Live` faces is gone; the new rule covers the same element, so it stays hidden exactly as before.
- **What can change on screen.** An element that carries `hidden` and was shown anyway by its class's `display` (or by an inline `display`) is now hidden; remove the attribute to show it, as the `Live` refresh and the escapes already do. Regenerating a face rewrites `style.css`, the page's CSS in `src/gen/shell.mjs` and nothing else.

## 0.14.1 (2026-10-17)

Adds to 0.14.0 and narrows one thing it did: **reads that are not a `Live` Block's read no longer carry a token.** The token's form, the socket, the signal and `YumemiLive` are as they were.

- **Tokens only for `Live` Blocks' reads (changed from 0.14.0).** In 0.14.0 every read Service with a root Entity answered with an `x-yumemi-live` token. A public read (an `Anyone` clause in its `allow`) thereby handed a token to anyone, signed in or not, and that token heard every write under the same root as it committed, including writes the public may not see (one word, no body, but at any time). Now the `live` table in the api's `src/gen/registry.mjs` lists, besides every write with a root Entity, only the read Services of Blocks that some face's Page places as `Live`; the generator knows them because it writes the api and the faces in one run. Any other read answers without the header (not an empty one). A page holding a 0.14.0 token gets the new rule's token, or none, when it next reads. The socket checks the token, not the table, so a 0.14.0 token (one taken from a public read, say) still opens a socket and hears until it expires, at most one hour after the upgrade; changing `YUMEMI_LIVE_KEY` without `YUMEMI_LIVE_KEY_PREVIOUS` when upgrading refuses those tokens (`signature`) and the `Live` pages read again for new ones, while sockets already open end at their token's expiry at the latest. Apps whose reads were never `Live` see the read rows leave `registry.mjs` and nothing else.
- **`Live` on a public read stops the generator (exit 4).** A `Live` Block whose read Service has an `Anyone` clause is a contradiction (`… の allow に Anyone がある …`): its token would let anyone hear the root's writes. So does a `Party` × `NoOwner` clause, in any `at` (`… の allow の句 Party(owner: NoOwner)は session があれば誰でも root のどの行も通す …`): anyone with a session passes on any row of the root, so a signed-in third party, which in an app where anyone may sign up is anyone, could hear the root's writes. A clause the generator cannot read (a constant, a spread, an `allow` that is not a List literal) stops it too (`… の allow の句が読めない: …`), since it cannot tell. An Entity subject × `NoOwner` (`Staff`, `AsFan`, `allow.staff`) is named in a warning (exit 0). Make the Block's read one only the root's parties pass: every clause's `owner` `Self` or `Via<Entity>Party` (a chat read allowed as `AsMember` × `ViaMemberParty` and `AsGuest` × `ViaGuestParty` passes). This narrows who holds a token, not what it hears: a party of the root still hears the time of writes under that root it may not read itself, which is ★'s call.

- **The fragment answer serves `Fixed` Blocks too.** A GET of a page URL with `x-yumemi-block: <name>` answers for every `Fixed` Block of the Page's `sp` placements, on every face, not only for `Live` Blocks. Gate, Vars, session and reads are the same as for the page (the Block's read Service and the Page's and Layout's reads that are not `optional`); a Block that reads no Service is drawn from the Vars. The answer is `<style>` and `<yumemi-block name>` (`display: contents`, no token). Layout Blocks, `Widget` Blocks and names the Page does not place stay 404, before any read.
- **`yumemi.block` on every face with escapes.** `mount(element, yumemi)` gets `yumemi.block(name, { href })` whether or not the face has `Live`. For a `Fixed` Block it returns a detached `<yumemi-block href>` with its style rules added; calling it again with the same URL reads the placed element again and applies it in place (the morph of `Live`). It returns `null` when no fragment comes, and never reloads the page for a `<yumemi-block>`.
- **The client runtime is split.** `yumemi/front/block.mjs` holds the fragment fetch, the style rules and the morph; `yumemi/front/live_block.mjs` (tokens, socket, scroll, `el.fresh`) builds on it. A face without `Live` bundles `block.mjs` only, and only when it has escapes.
- **Generated output.** Faces whose Pages place `Fixed` Blocks get `block_<name>` functions in `src/gen/load/**`, a `blocks` table and the fragment answer in `src/gen/shell.mjs`, and the header check in `src/gen/gate.mjs`. The page HTML is unchanged.
